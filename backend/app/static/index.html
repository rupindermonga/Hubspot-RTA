How does this app work?

What it does: compares addresses from your Hubspot contact list against the RTA (Ready to Activate) database. For each Hubspot contact, it checks whether the address exists in RTA and brings back the RTA address + status.

How matching works (5 passes, safest to riskiest):

  1. Exact — street + postal code match perfectly after normalization (Street/ST, Road/RD, etc. standardized; PO Boxes / Suites stripped).
  2. Direction strip — same as above, but trailing N/S/E/W ignored. "28 Alton Lane" matches "28 Alton Lane East".
  3. Fuzzy / alias — known street-name variants treated as one. "Findlay Hill Rd" = "Findlay Rd", "Panache Northshore Rd" = "Panache N Shr Rd". (Aliases visible in the sidebar.)
  4. Unit suffix strip — "-U1" / "-U2" stripped. "97-U2 Pioneer Rd" matches "97 Pioneer Rd".
  5. Street-only (opt-in) — match on street alone, ignoring postal code. Risky because different towns can share a street name.

Why Hubspot Matched can differ from RTA In Hubspot:

Multiple Hubspot contacts can live at the same RTA address (e.g. two people at 123 Main St). The Hubspot count counts rows; the RTA count counts unique RTA records.

Color coding (Hubspot sheet in the downloaded Excel):

  • White — Exact match.
  • Yellow — Fuzzy match (alias / direction / unit).
  • Orange — RTA has conflicting statuses for this address.
  • Red — Street matched but postal codes differ — verify manually.

Color coding (RTA sheet):

  • Purple — NOT in Hubspot (flag for Redrabbit update).
  • White — matched to at least one Hubspot record.

Postal code correction: common typos like "O" vs "0" and "I" vs "1" are auto-fixed (e.g. "POM" → "P0M"). Empty / NaN postal codes won't false-match.

RTA Status Compare

Compare two RTA snapshots — find what was added, removed, status-changed, or conflicting in the new file.

How does this work?

What it does:

  1. Removed — addresses present in the old file but gone in the new file.
  2. Added — addresses that appeared in the new file.
  3. Status Changed — same address in both, but the RTA Status moved (e.g. In Construction → RTA).
  4. Conflicts in New — same address appearing more than once in the new file with different statuses.

Address matching: uses the same normalization as the matcher (case + abbreviations standardized, alias map applied, postal-code typos auto-corrected, trailing direction and unit suffixes stripped) so minor format differences between snapshots don't falsely show as add/remove.

Color legend:

  • Purple — Removed (in Old, not in New).
  • Blue — Added (in New, not in Old).
  • Green — Status changed: In Construction → RTA (forward).
  • Yellow — Status changed: RTA → In Construction (regression — review).
  • Orange — Conflict in New file (multiple statuses for the same address).
